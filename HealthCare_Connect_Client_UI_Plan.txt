01 / THE OPPORTUNITY
One connected experience for finding and booking care
The UI plan turns the current React prototype into a clear, role-aware patient and doctor experience.
For patients
Discover doctors, compare profiles, choose Phone / Clinic / Home Visit, pay and track appointments.
For doctors
Create a professional profile, submit registration details, follow verification and manage practice availability.
For public visitors
Understand the service, browse doctors and policies, then choose whether to create an account.

===== SLIDE 15 =====
11 / INTERACTION STATES
Design the moments around the happy path
Every data-dependent screen needs feedback before, during and after a user action.
Loading
Skeletons or clear progress; prevent duplicate submit; keep context visible.
Validation
Field-level guidance, accessible error text and a clear next step.
Empty
Explain why nothing is shown and offer a useful action (search again / book).
Success
Confirm what happened, show a reference where relevant and link to next action.
Error
Say what failed, preserve user input and offer retry or support.
High-risk moments to review: slot becomes unavailable • OTP invalid/expired • upload rejected • verification needs more information • payment pending or failed.

===== SLIDE 19 =====
15 / RESPONSIBILITY BOUNDARY
The interface guides the journey; the backend owns trusted outcomes
Agree contracts early so the frontend can show accurate status without becoming the source of truth.
Frontend / React
Render routes, layouts and responsive UI
Collect and validate user input
Manage local interaction and step progress
Call APIs and show loading / empty / error / success
Display verified server status and payment result
Provide accessible, recoverable user journeys
Backend / services
Authenticate users and enforce roles
Own doctor, schedule and appointment records
Prevent slot conflicts and confirm booking
Create Razorpay orders and validate callbacks
Securely store documents and review decisions
Send OTPs, email/SMS updates and reminders
The existing prototype does not demonstrate a production API, live Razorpay integration, real OTP delivery or verification provider.
